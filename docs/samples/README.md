# 端到端样例（真实 LLM 人工验收 · T1.5）

这里存放**连真实 LLM 跑出来的真实问诊记录**，用于：

- **回归对照**：改了提示词 / 换模型 / 改编排后，跑同一个用例，与这里的输出逐条比对；
- **效果展示**：给非技术同事看系统实际产出什么；
- **验收留痕**：证明「这条链路在真实模型上跑通过」。

> 与自动化测试的区别：`e2e_tests/` 用 stub 或只读端点验证链路，
> 不消耗算力也不需要人在场；这里的样例是**人工验收产物**，
> 输出质量由人判断，因此**每次改动关键提示词后应重新归档一次**。

## 如何生成

```powershell
cd tcm_work/e2e_tests
$env:HARNESS_LLM_API_KEY = '<LM Studio 令牌>'   # 若服务端开启了鉴权
.\run_manual_e2e.ps1 -Case damp-heat
```

每个用例一个目录：

| 目录 | 用例 | 自动检查 | 人工审阅结论 | 耗时 |
|---|---|---|---|---|
| [`damp-heat/`](./damp-heat/README.md) | 脾胃湿热 | 6/6 PASS | 证候判对，**方剂与主证不对口**（给了清肝胆湿热的龙胆泻肝汤） | 128s |
| [`wind-cold/`](./wind-cold/README.md) | 风寒感冒 | 6/6 PASS | 证候与治则正确，**麻黄汤药味写错**（多出白术） | 126s |
| [`red-flag/`](./red-flag/README.md) | 红旗症状 | 7/7 PASS | 拦截正确、话术得当（直接让打急救电话）、留痕完整 | 89s |

> 均为 2026-08-30 在 `google/gemma-4-12b-qat` + Docker 化 harness 上跑出，
> 端到端 7 步（red-flag 为 6 步，治疗步被拦截）。
> 详细审阅意见见各目录 README 第 7 节。

目录内文件：

- `chat.json`：服务端原始响应（`steps` / `structured` / `trace` / `report_id`）
- `report.json`：服务端归档快照（已脱敏）——回查与存证验证用
- `README.md`：人读版报告（输入、输出摘要、耗时、工具调用、验收结论）

> 归档内容落盘前已脱敏（手机号 / 身份证 / 邮箱 / 长数字串），
> 但**样例中的主诉是构造的用例文本**，不含真实患者信息。
